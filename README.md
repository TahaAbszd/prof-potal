# پرتال اساتید دانشگاه هرمزگان

پرتال با Next.js و بک‌اند Go/Gin ساخته شده است. پروفایل‌ها و حساب‌ها در SQLite ذخیره می‌شوند و Redis داده‌های عمومی پرتکرار را کش می‌کند؛ استاد می‌تواند پروفایل خودش را ویرایش کند و مدیر می‌تواند دانشکده، استاد و حساب جدید بسازد، پروفایل‌ها را ویرایش کند و گذرواژه استاد را بازنشانی کند. رزومهٔ فارسی هر استاد به‌صورت PDF از اطلاعات ثبت‌شده تولید می‌شود.

## پیش‌نیازها

- Node.js 22 یا جدیدتر
- Go 1.26 یا جدیدتر
- Chrome یا Chromium روی سرور برای تولید PDF
- Redis روی پورت ۶۳۷۹ یا نشانی تنظیم‌شده در `REDIS_URL`

## راه‌اندازی محلی

```bash
npm install
cp backend/.env.example backend/.env
```

در `backend/.env` مقدارهای `BOOTSTRAP_ADMIN_PASSWORD` و `BOOTSTRAP_FACULTY_PASSWORD` را با دو گذرواژهٔ تصادفی و متفاوت (حداقل ۱۲ نویسه) جایگزین کنید. `CHROME_BIN` باید مسیر فایل اجرایی Chrome/Chromium باشد. این فایل و پایگاه داده در `.gitignore` قرار دارند.

برای کش، `REDIS_URL` را روی نشانی Redis بگذارید. مقدار پیش‌فرض محلی `redis://127.0.0.1:6379/0` است؛ `REDIS_PREFIX` فضای کلیدهای این پرتال را مشخص می‌کند. Redis باید قبل از بک‌اند اجرا شود. اگر Redis موقتاً قطع شود، API داده‌ها را از SQLite می‌خواند؛ وضعیت اتصال در `/api/health` دیده می‌شود.

دو ترمینال باز کنید:

```bash
npm run dev:api
npm run dev
```

پرتال: `http://localhost:3000/ostad` · ورود: `http://localhost:3000/login` · پنل: `http://localhost:3000/dashboard`

در اولین اجرای بک‌اند، حساب مدیر با نام کاربری `admin` و دو حساب استاد با نام‌های `golzari` و `daryanavard` ساخته می‌شوند. گذرواژهٔ مدیر از `BOOTSTRAP_ADMIN_PASSWORD` و گذرواژهٔ اولیهٔ دو استاد از `BOOTSTRAP_FACULTY_PASSWORD` خوانده می‌شود. این متغیرها فقط هنگام ساخت حساب اولیه به کار می‌روند؛ تغییر بعدی آن‌ها گذرواژهٔ حساب موجود را عوض نمی‌کند. پس از ورود، از پنل برای تغییر گذرواژه استفاده کنید.

## مسیرها و API

- `/ostad`: فهرست عمومی، جست‌وجو، فیلتر دانشکده و صفحه‌بندی ۲۰تایی
- `/ostad/[slug]`: پروفایل عمومی و دکمهٔ دانلود رزومهٔ PDF
- `/login`: ورود استاد یا مدیر
- `/dashboard`: ویرایش پروفایل و مدیریت حساب‌ها بر اساس نقش؛ مدیر می‌تواند برای پروفایل واردشده حساب ورود بسازد
- `/api/health`: وضعیت بک‌اند
- `/api/professors?q=&faculty=&page=` و `/api/professors/:slug`: اطلاعات عمومی و فهرست صفحه‌بندی‌شده
- `/api/faculties` و `/api/admin/faculties`: فهرست دانشکده‌ها و افزودن دانشکده توسط مدیر
- `/api/professors/:slug/view` و `/api/search-events`: ثبت بازدید پروفایل و جست‌وجوی دقیق
- `/api/professors/:slug/resume.pdf`: رزومهٔ PDF
- `/api/auth/*`: ورود، خروج، نشست و تغییر گذرواژه
- `/api/admin/professors/:slug/account`: بررسی و ساخت حساب ورود برای پروفایل موجود توسط مدیر

Next.js درخواست‌های `/api/*` را به Gin در پورت ۸۰۸۰ منتقل می‌کند. `API_INTERNAL_URL` و `API_PROXY_TARGET` برای تغییر مقصد داخلی قابل تنظیم‌اند. در محیط انتشار، `PUBLIC_ORIGIN` را روی آدرس HTTPS عمومی، مثلاً `https://ostad.hormozgan.ac.ir`، بگذارید و `COOKIE_SECURE=true` تنظیم کنید. دو سرویس Next.js و Go باید هم‌زمان اجرا شوند؛ پایگاه داده و فایل `.env` را در فضای پایدار و خصوصی نگه دارید.

فهرست اساتید، پروفایل عمومی و فهرست دانشکده‌ها با مهلت انقضای دو دقیقه در Redis نگه‌داری می‌شوند. تغییر پروفایل، ایجاد استاد یا دانشکده، و ثبت بازدید یا جست‌وجو نسخهٔ کلیدهای مرتبط را عوض می‌کند تا درخواست بعدی دادهٔ تازه بگیرد. نشست‌ها، گذرواژه‌ها و آمار اصلی فقط در SQLite نگه‌داری می‌شوند.

ترتیب فهرست برای همه یکسان و غیرقابل‌تغییر است: مجموع بازدید و جست‌وجوی دقیق بیشتر، سپس بازدید بیشتر، سپس مرتبهٔ علمی از استاد تمام تا مربی، و در نهایت نام به ترتیب الفبایی بدون حساسیت به بزرگی و کوچکی حروف. هر بازدید و جست‌وجوی دقیق برای هر مرورگر و استاد حداکثر یک بار در روز ثبت می‌شود.

## وارد کردن اساتید از سایت رسمی

در ۱ اکتبر ۲۰۲۶، فهرست عمومی [پرتال رسمی اساتید دانشگاه هرمزگان](https://ostad.hormozgan.ac.ir/ostad/) شامل ۲۸۳ پروفایل یکتا بود. خروجی استخراج‌شده در `data/imports/official-faculty-profiles.json` قرار دارد و تصاویر عمومی در `public/images/official-faculty/` ذخیره شده‌اند. سه پروفایل موجود با نام تطبیق داده شدند؛ ۲۸۰ پروفایل تازه به SQLite افزوده شد. برای یکسان‌سازی محتوای آن سه پروفایل با منبع رسمی، دستور `sync-official-existing` را اجرا کنید؛ آدرس پروفایل، حساب‌های ورود و آمار بازدید حفظ می‌شوند. همین دستور مرتبهٔ قدیمی «استاد» را در همهٔ پروفایل‌ها به «استاد تمام» تبدیل می‌کند. نسخه‌های پشتیبان در `backend/data/backups/` قرار دارند.

برای استخراج دوبارهٔ فهرست رسمی و افزودن استادان تازه:

```bash
python3 -m pip install -r scripts/requirements-import.txt
python3 scripts/fetch_official_index.py
python3 scripts/export_official_profiles.py --fresh
python3 scripts/download_official_images.py
cd backend && go run . import-official ../data/imports/official-faculty-profiles.json
```

ورود داده‌ها تراکنشی و تکرارپذیر است و به پروفایل‌های موجود دست نمی‌زند. برای اساتید تازه، حساب و گذرواژهٔ پیش‌فرض ساخته نمی‌شود؛ مدیر می‌تواند از پنل برای هر استاد حساب اختصاصی تعریف کند. اسکریپت‌های استخراج به `curl` و `dig` نیاز دارند.

برای به‌روزرسانی سه پروفایل قبلی پس از استخراج، در حالی که Redis در دسترس است اجرا کنید:

```bash
cd backend && go run . sync-official-existing ../data/imports/official-faculty-profiles.json
```

## بررسی

```bash
npm run build
npm run lint
npm run test:api
```

فایل `data/professors.json` فقط برای پر کردن پایگاه دادهٔ خالی در اولین اجراست. در HTML اولیه دو نام متمایز وجود داشت و بخش بزرگی از اطلاعات علمی تکراری یا نمونه بود؛ پیش از انتشار عمومی، داده‌های اولیه را با اطلاعات رسمی دانشگاه بازبینی کنید. محتوای تازه از پنل مدیریت در SQLite ذخیره می‌شود و در پروفایل عمومی و PDF نمایش داده می‌شود.
